## evals 观测方案设计（只出方案，不动代码 —— 用户明确要求）

后续涉及本项目代码，一律先给方案 + 等用户确认，确认后才允许落盘。

分析了 LangGraph 实战项目（扫地机器人客服 Agent）的 evals 现状，设计了「采集 → 评估 → 门禁」三层观测方案，全部基于 LangGraph/LangSmith 原生能力。

- 环境：langgraph 1.2.11 / langchain 1.3.16 / langchain-core 1.6.2 / langsmith 0.12.2 / pytest 9.0.3；.env 已有 LANGSMITH_* 配置但未接上。
- 现有骨架问题：
  1. `evals/trace_handler.py` 的 `ToolTrace(BaseCallbackHandler)` 缺 import（`langchain_core.callbacks`），且只记工具名，无耗时/token。
  2. `evals/runner.py` 的 `capture_stream` 用 `i += chunk`，但 `execute_stream` yield 的是 dict → 必然 TypeError；resume 传空 dict，`user_decision_node` 里 `decision["user_decision"]` 会 KeyError。
  3. `cases.jsonl` 字段不统一（chat 类缺 user_id/month/decision）；`evaluators.py` 两函数均为 pass；`baseline.json` 为空。
  4. runner.py 在 import 期即改全局 business_config/memory_config，存在模块级副作用。
- 方案要点三层：
  - 采集：LangSmith tracing（env 开关）+ `stream_mode=["debug"]` task 级快照 + callback handler + `get_state`/`get_state_history` 状态回放。
  - 评估：确定性断言（工具序列/中断契约/错误泄漏/延迟预算）+ 轨迹匹配（expect_tools）+ LLM-as-judge（忠实度、报告相关性）+ 状态字段校验（quality_score、regenerate_count）。
  - 门禁：baseline 逐 case diff、阈值告警、产物归档、pytest 退出码进 CI。
- 建议新增文件：`evals/collector.py`、`evals/langsmith_eval.py`、`evals/langgraph.json`（支持 `langgraph dev` 起 Studio）。
